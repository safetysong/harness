# harness

Claude 작업장 표준(하네스) 원본입니다.
어떤 프로젝트든 같은 바닥판 위에서 일하고, 일의 성격에 맞는 세트를 하나 골라 얹습니다.
업무 내용·개인정보·비밀값은 넣지 않습니다(공개 저장소).

## 하네스가 뭐예요?
Claude가 일할 때 옆에 붙는 **안내판과 검사기**입니다.

- 안내판(시작 전): 세션이 열리면 진행상황과 완료 조건을 먼저 보여 줍니다.
- 검사기(끝난 뒤): 끝내려고 할 때 완료 조건을 실제로 확인하고, 안 되면 끝내지 못하게 합니다.
- 같은 실수가 두 번 나면 기록해 두고, 다짐 대신 장치로 막을 방법을 제안합니다.

## 바닥판(모든 프로젝트 공통)

| 장치 | 언제 | 하는 일 |
|---|---|---|
| 시작 안내 | 세션 시작 | 진행상황·완료 조건·다음 할 일을 보여 주고 `[장치 상태]` 한 줄을 붙임 |
| 한국어 지킴이 | 질문·요약 보낼 때, 도구 뒤, 답 끝 | 사용자에게 보이는 글이 영어이거나 「—」 대시가 있으면 다시 쓰게 함 |
| 저장소 지킴이 | 도구 쓰기 전 | 다른 저장소를 붙이거나 건드리려 하면 사용자 허락을 받게 함 |
| 끝 점검 | 답 끝 | 파일을 바꿨는데 진행상황을 안 적었거나, 완료 조건 확인 명령이 실패하면 끝내지 못하게 함(한 답에서 두 번까지만). 프로젝트에 옛 진행상황 검사 장치가 있으면 진행상황 부분은 꺼서(`progress_check: false`) 두 번 막지 않음 |
| 프로젝트 자체 지킴이 | 사용자에게 보이는 글 보내기 직전, 답 끝 | 프로젝트에 `.claude/hooks/work_guard.py`가 있으면 돌림. 보내기 직전에는 막고, 답 끝에는 막지 않고 경고만 남기며 건수를 세어 `[장치 상태]`에 최근 7일 건수를 보여 줌 |
| 실수 기록 | 지킴이가 막았을 때, 완료 조건 실패 | 같은 종류가 두 번이면 모아 둠. 도구 고장(시간 초과, 인터넷 끊김, 명령 실패)은 실수와 섞지 않고 따로 셈. 읽기 전용 세션에서는 남기지 않음 |
| 장치 숫자 기록 | 늘 | 막은 횟수·경고·실수·도구 고장을 모아 둠. 훅은 git에 들어가는 파일을 고치지 않고, PR 올릴 때 `report` 한 줄로 `.claude/harness-stats.jsonl`(하루 한 줄)과 `실수기록.md` 에 옮김 |
| 금지 목록 | 늘 | 강제 푸시·`sudo`·비밀 파일 읽기 같은 위험한 명령을 막음 |

## 세트(보통 하나, 두 개도 됨, 안 골라도 됨)

| 세트 | 어떤 일 | 자동 검사 | 검토 에이전트 |
|---|---|---|---|
| A-research | 글·조사 | 각주 번호와 각주 설명의 짝 | 근거확인자(인용 원문 대조·출처 확인) |
| B-app | 앱·코드 | 바뀐 파일 문법(.py .js .json .sh .html) | 코드검토자 |
| C-submission | 제출물(공모전 등) | 요강의 필수 항목·분량·형식, 시작할 때 마감까지 남은 날 | 심사위원 |

한 저장소에 성격이 다른 일이 섞여 있으면 `"set": ["A-research", "B-app"]` 처럼 두 세트를 같이 씁니다.
세트 없이 바닥판만 쓰려면 `"set": "core"` 입니다.

## 프로젝트에 까는 법
Claude에게 이렇게 말하면 됩니다.

> 이 프로젝트에 하네스 C 깔아 줘

Claude는 [bootstrap/install.md](bootstrap/install.md) 순서대로 합니다. 요약하면:

1. 프로젝트에 받기 장치 `.claude/harness-sync.sh` 하나를 넣습니다.
2. `.claude/harness.json` 에 세트 이름과 저장소 이름을 적습니다.
3. 받기 장치로 하네스를 받고(`sync`), `upgrade` 한 줄로 받기 장치와 훅 설정을 맞춥니다.
4. `CLAUDE.md`, `진행상황.md` 틀을 채웁니다.
5. 다음 세션부터 켜집니다.

PC에서는 플러그인으로도 쓸 수 있습니다: `/plugin marketplace add safetysong/harness` 뒤 `/plugin install harness`.
플러그인과 프로젝트 설치를 같이 하면 훅이 두 번 도니 하나만 씁니다.

## 업데이트되는 원리
1. 이 저장소 main에 새 판이 병합되면, 세트마다 묶음 파일(`dist/세트.tar`)과
   승인 목록(`signed/approved.json`, 묶음마다 지문 하나)이 같이 바뀝니다.
2. 각 프로젝트에서 세션이 시작할 때(처음은 늘, 이어 하기는 30분에 한 번) 받기 장치가 main의 승인 목록을 봅니다.
3. 판 번호가 다르면 묶음을 받아 지문을 대조하고, 같을 때만 `.claude/harness-state/harness`(git에 안 들어감)에 풉니다.
   훅은 그 판으로 돌고, 저장소의 `.claude/harness` 는 그대로라 `git pull` 이 깨지지 않습니다.
4. 결과는 `[장치 상태]` 줄에 나옵니다. 예: 「새 판 0.2.0 받음(전 판 0.1.0)」.
   - 훅 내용(검사 방법·문구)은 받은 그 시작부터 바뀝니다.
   - 받기 장치나 훅을 거는 자리·금지 목록(settings)까지 맞추려면 `bash .claude/harness-sync.sh upgrade` 한 줄을 돌립니다.
     받기 장치도 승인 목록 지문을 거친 묶음에서만 바꿉니다. settings 바뀐 것은 그다음 시작부터 켜집니다.
   - 저장소에 실린 판과 다르면 `[장치 상태]`에 「upgrade PR 필요」가 나옵니다. `upgrade` 로 `.claude/harness` 에 싣고 PR로 넣습니다
     (다음에 네트워크가 안 돼도 그 판으로 돎).

## 위험과 막는 법
| 위험 | 막는 법 |
|---|---|
| 누가 묶음 파일을 바꿔치기함 | 받은 묶음의 지문(sha256)이 main의 승인 목록과 다르면 받지 않고 지금 판을 씁니다. 「경고」가 `[장치 상태]`에 뜹니다 |
| 승인 안 된 고침이 퍼짐 | 지문은 main에만 있는 승인 목록에서 읽습니다. main은 PR과 검사(Actions)를 거쳐야 바뀝니다 |
| 승인 목록과 원본이 어긋남 | Actions가 원본으로 묶음을 다시 만들어 지문이 승인 목록과 같은지 매번 확인합니다 |
| 네트워크가 안 됨 | 조용히 지금 판을 씁니다. 일은 멈추지 않습니다 |
| 이상한 묶음(바깥 폴더로 빠져나가는 파일) | 풀기 전에 파일 이름을 검사하고, 이상하면 받지 않습니다 |
| 하네스가 고장 남 | 훅이 고장 나면 막지 않고 통과시킵니다. 일부러 막을 때만 막습니다 |
| Claude가 하네스 파일을 몰래 고침 | 금지 목록에 `.claude/harness/` 고치기를 넣었습니다 |
| 받기 장치 자체 | 세션 시작 때는 스스로 바꾸지 않습니다. `upgrade` 를 돌릴 때만, 지문이 맞은 묶음 안의 받기 장치로 바꿉니다 |

지금의 지문 확인은 「main에 병합된 판」이라는 것까지만 증명합니다. 공개키 서명은 다음 판에서 정합니다.

## 판 올리는 법(Claude용)
1. 작업 브랜치에서 `core/`·`sets/` 를 고치고 `VERSION` 을 올립니다.
2. `python3 tools/build_bundles.py` 로 묶음과 승인 목록을 새로 만듭니다.
3. `bash tests/run.sh` 가 통과해야 합니다.
4. 스크립트를 고친 PR은 병합 전에 `/code-review` 를 한 번 돌리고 결과를 PR 설명에 적습니다.

## 폴더
```
core/        바닥판: 훅(hooks/), CLAUDE.md 틀, 진행상황.md 틀, settings 묶음
sets/        세트 A·B·C: 안내(guide.md), 검사기(checks/), 검토 에이전트(agents/)
bootstrap/   받기 장치(harness-sync.sh)와 까는 순서(install.md)
dist/        세트별 묶음(자동으로 만듦)
signed/      승인 목록 approved.json(자동으로 만듦)
tools/       묶음 만드는 도구
tests/       훅 시험(bash tests/run.sh)
.claude-plugin/  PC 플러그인 설명
```

필요한 것: `bash`, 파이썬 3(3.10 이상 권장, 시험은 3.10과 3.13에서), 하네스를 받을 때 인터넷.

### 윈도 PC에서
- **Git for Windows**를 깔아 주세요. git과 bash가 같이 깔립니다. Claude Code가 bash를 못 찾으면 하네스 훅이 돌지 않습니다.
  이때도 일은 막지 않고(훅마다 `onFailure: continue`) 장치만 꺼집니다. bash를 다른 곳에 깔았으면 `CLAUDE_CODE_GIT_BASH_PATH` 로 알려 줍니다.
- **파이썬**(python.org)을 깔아 주세요. `python3`, `python`, `py` 순서로 찾습니다. 못 찾으면 시작할 때
  「[장치 상태] 파이썬(3.8 이상)을 찾지 못해 하네스 장치가 모두 꺼져 있어요」가 나옵니다.
- 윈도의 **PowerShell 도구**도 지킴이가 봅니다. 저장소 지킴이는 PowerShell 명령도 검사하고, 금지 목록에는 git 위험 명령(강제 푸시 등)의 PowerShell 판이 있습니다. 파일 지우기 같은 PowerShell 명령은 아직 금지 목록에 없습니다.
- 받기 장치(`.claude/harness-sync.sh`)는 세션 시작 때 스스로 바뀌지 않습니다. `upgrade` 를 돌려야 바뀝니다.
- Claude Code 2.1.295 이상이 필요합니다(`onFailure` 칸).
